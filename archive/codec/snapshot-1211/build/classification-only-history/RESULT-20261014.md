# A1599 C0 分类修正与输出同步边界（离线）

本次完成了 Apple C0 下游静态追踪、两个生产文件的独立候选补丁、失败先行的回归和模块构建。**`0x600644d5` 是原厂 class `0x10`；它不应仅因非零被本地标成 firmware error，也不构成输出可读或像素成功的证明。** 新候选目前明确不授予 guard/output 检查资格。

没有 USB、设备文件、MMIO、目标日志新查询、输出新读取、模块加载/替换、重启或软件安装。所有执行均为宿主普通文件分析、用户态测试和离线编译。冻结 `4367…` 与 `c97f…` 保持不变。

## 四种独立结论

| 层次 | 依据 | 当前 `600644d5` 的结论 |
|---|---|---|
| 消息合法 | ID、长度、字段存在性、expected fence；真实 `c0_parse` | 12 bytes、C0、fence=1，合法 |
| 原厂响应分类 | 原始接收器以 flags bit27 选择 0x10/0x8010 | class 0x10，非 class 0x8010；其他非零 bit 未完整解释 |
| 输出可检查 | 独立的任务完成、surface/DMA 可见性契约 | 未闭合；新候选 `output_inspection_allowed=false`，不读 guard/输出 |
| 像素验证成功 | 实际取得的固定长度快照、guard、已知布局与软件参考逐像素比较 | 未执行；保持 `pixels_compared=0 decode_success=unclaimed` |

`a1599_decode_submit_once()` 返回 0 仅表示合法 class 0x10 的响应处理结束。新日志分别输出 `c0_record_valid`、`c0_native_class`、`c0_native_error`、`output_inspection_allowed`、`output_sync=unproven`。不能把返回 0、bit27=0、status=0、guard 完整或两个快照相同单独称为解码成功。

## 同步仍缺什么，以及排除什么

1. 需要解析提交记录 +0x10 所指对象的实际动态类型/vtable，并定位 `+0x220` / `+0x228` 的真实实现，确定 deviceLockSurface/deviceUnlockSurface 对这类输出的 cache、mapping、设备拥有权和通知顺序做了什么。目前已找到调用对象、参数、调用点和上下游关联，但没有证明该实现及其与 Linux `dma_alloc_coherent` backing 的对应关系。
2. 还没有从固件或总线契约证明 C0 发布早于/晚于最后一次 output DMA store，以及该关系如何被 Linux 的读取屏障观察。Linux 当前使用 coherent allocation 并不独自证明 firmware 的完成时序；加 `dma_rmb()` 也不凭空建立设备完成事件。
3. 原厂 ISR 会消费并检查当前批次；本 harness 为单次实验保留 consumer，只接收一条 bounded message。已证明这个差异，但**没有认定 consumer 推进就是缺少的 DMA flush，也没有据此改 consumer**。
4. 已排除“非零 flags 必为错误”“bit27 清零就可读输出”“status 全零就可先读 guard”“两次50ms相同必然永久停止DMA”“+4=3 可直接当有效宏块索引”。未把 `bdef7bdf` 解释成 MMU 错误，未给 bit7/29/30 猜测语义。

允许 future output 检查至少需要针对实际 backing 建立上述完成/可见性契约，明确门禁实现及实验范围，再另行授权新代码试验。当前候选只实现正确分类和明确拒绝输出检查；**不能仅把一个 bool 改 true 就作为后续输出方案**。
