## 独立 oracle 的范围与输入

新增 `host-regressions/apple_emit_oracle.c` 是无 libc 的 AArch64 Linux 用户态程序，经现有 `qemu-aarch64-static` 运行。它把原始 kernelcache 的副本装入进程内存，直接执行 Apple producer **`0xfffffff00869726c` / file 0x169326c** 至原始返回；包括 picture 配置分支、slice 配置函数、FE/main emitter、命令 header 和末尾消息组装。不是调用候选 serializer 来生成期望值。

原始代码的高 VA 被整体平移到低用户地址，如 `0xfffffff00869726c` → `0x0869726c`。本路径代码与读取的静态表使用 fileoff=VA−`0xfffffff007004000`；未把该映射当成整个 Mach-O 的通用装载器。没有执行内核或固件、没有仿真设备。运行过程中仅访问两个普通输入文件并输出结果。

只在进程内副本替换三个内存例程及错误出口：

| 原始 VA / file offset | 替代内容 |
|---|---|
| fffffff0075b5740 / 0x5b1740 | 普通用户内存 memset |
| fffffff0075b56c0 / 0x5b16c0 | 普通用户内存 bzero |
| fffffff0075b5510 / 0x5b1510 | 普通用户内存 memcpy |
| fffffff008677de4 / 0x1673de4 | 立即打印 return-PC 并退出失败；测试不允许忽略 Apple 断言 |

另把 **0x86971b4** 在内存副本中改为 RET，单独重放 **0x8697190..0x86971b0** 的 metadata-store 基本块，验证 C+538→B+28。此块在主 producer 返回后调用；没有把整个 completion/submit 函数算作已执行。原始文件不被修改。资源 lookup `0x869648c`、命令分配/游标 helpers、packers 均执行原始指令，没有替换它们。

独立 `fixture_bits.py` 直接解析 57-byte fixture 的 SPS/PPS/slice，得到 32x32、frame_mbs_only=1、MBAFF=0、baseline 8-bit 4:2:0、slice_type=7→2、pic_init_qp_minus26=-3、slice_qp_delta=-3、deblock_idc=1、alpha/beta=0、已消费 header=32 bits。输入 hash 在测试中强制核验：

- kernelcache：`76269e79b4715783b95407acbb54df2369116c76709a03f24e0fe95924199eb9`。
- fixture：`839967e0bd3c887029c3a8517f3f5ed0aea57b0a567ac9ac700a85f92458af31`。

compact P/T 按已反汇编桥接关系填入；**没有完整运行 Apple SPS/PPS/slice parser**。P+6 为 0x1850，其中 bit11 是 Apple 桥接在 `0x8693344` 明确置位的 producer 特性，bit12 来自 frame_mbs_only。无 weighted prediction 时 `0x8692f08..0x8692f0c` 写 T+17/+18=5，因此最终 0x1024 word=0x55，不是从候选常量抄来的输入。Scaling lists 使用 baseline 缺省 flat16。

宿主条件明确固定为：第一 picture/slice、空参考列表、P.byte4=0、C+398=C+15f0=0、direct primary output、stride64、plane offsets0/2048、候选现有资源地址。合成测试另使用 0x50000000..0x56000000 地址，验证地址传递。内存映射、firmware preload 内容、硬件 register 接受性不在 oracle 覆盖范围。

## C+0x538 完整的相关传播

全文代码位置均是 12.5.8 unslid VA。下面简写 0x869xxxx 的完整前缀为 `0xfffffff00`；文件偏移为该简写地址减 0x7004000。

| 完整 VA / 文件偏移 | 作用与本 fixture 路径 |
|---|---|
| fffffff0086974e8..7508 / 0x16934e8..3508 | P+6 bit0=0；写 C+538=1；bit1=0 则 C+534=2。进入 7880 公共写入点。 |
| fffffff008696818..6824 / 0x1692818..2824 | 分配 **0x30-byte 独立宿主记录 B**，保存到 C+c78 表。B 不是 current-picture DMA backing 本身。 |
| fffffff0086964a8..64d0 / 0x16924a8..24d0 | slot→C+50 映射→C+c78 指针表，选到 B，放入 C+590。B+0 指向 current-picture mapping，mapping+10 才是 codec IOVA。 |
| fffffff008697190..71b0 / 0x1693190..31b0 | B+1c=P.byte4 bit7，B+18=P.half6 bit1，**B+28=C+538=1**。原始基本块重放确认实际 store。 |
| fffffff008698aac..8ab4 / 0x1694aac..4ab4 | 检查 T+16==1；本 normalized I=2，跳到 8e38，绕过参考图像编码。 |
| fffffff008698b60..8b68 / 0x1694b60..4b68 | 参考处理另一个入口同样检查 T+16==1；本 fixture 跳过。 |
| fffffff0086995f4..9608 / 0x16955f4..5608 | 参考 B+28 与1比较，`!=1` 放入将要发出的 word bit4；B+18 放 bit2。此代码本次不执行。 |

原始片段中的其他 `#0x538` 命中多为不同外层对象的 **64-bit 指针成员**，不应与 C 的 32-bit picture mode 混同。`0x8698b2c` 的 `+0x28` 则是 P 中的参考 POC 数组，不是 B+28。当前图像地址的两个消费者 `0x8698944..8960`、`0x86992a4..92f8` 使用 mapping/output layout，不读取 B+28。

测试将 B+28 预置为3，再以相同 progressive I fixture 执行整个 producer，命令 544 bytes 完全不变；随后重放 metadata store，B+28 被更新为1。这个动态结果与上述静态排除路径一致。没有把 B+28=1 错写进 DMA backing，也没有新增第四个常量。

## 回归及构建

1. 先复制冻结生产源码到本独立目录，新增独立 oracle 测试，然后在未修正源码上运行：**退出1**，准确报告 word1/50/60 三处不匹配。证据 `build/ORACLE-RED.log`。
2. 仅应用 `PRODUCTION-CHANGES.patch` 中的三处修改，再运行同一 oracle：**退出0，136/136匹配**。证据 `build/ORACLE-GREEN.log`。
3. 原始指令路径测试覆盖 progressive 两种 P4 极性、MBAFF、top field、bottom field，共五条模式分支；每条验证 C534/C538/B28。另验证历史 B28=3 不污染首个 I-slice；slice delta+1 只改变 QP word51/61，不改变 H+4。
4. 同时验证合成地址布局和实际候选地址布局；实际布局的候选 builder 与 Apple producer **544/544 bytes 相同**。
5. 8 个现有 C host regressions 通过：diagnostics、layout、lifetime、stream、one-shot submit mock、DMA mask contract、INIT MMIO fake backend、ring capacity。16 个候选静态 contract assertions、3 个 output comparison tests、M2H snapshot source/exact callback tests 通过。见 `build/HOST-REGRESSIONS.log`。没有运行旧 resource_probe 的设备测试。
6. kernel module 编译、链接、MODPOST 成功；未启用或执行内核 KUnit，未加载模块。

## 仍未闭合的字段与边界

- **P.byte4 bit7 的上游宿主记录**：已定位 `0x8693028..3038`（file0x168f028..f038）读取 `D+2e60+0x88*slot` 记录的 byte55 并填入此 bit；本次未完整追溯该记录 byte55 的所有写入。oracle 固定为0，与冻结流的 FE/RENDEC 0x30108一致。将其改成1时 progressive 的 C534仍为2，但图像几何/场标志 word可变；因此不能把这项宿主输入宣称为完整独立 parser 证明。它不影响本次三个已证明修正。
- 模式分支相关 C534/C538 已闭合；C+398/C+15f0/direct-output policy、资源映射/尺寸/stride、P.byte5/参考列表的整个宿主生命周期、baseline scaling-list 构造均未完整运行 Apple 上游分配/初始化流程。本次在现有候选状态下验证传递及命令生成，不宣称所有 policy 已闭合。
- 没有证明 current-picture / intra / preload backing 内部数据、DMA/IOMMU/cache 状态、ID81 wire及固件 ABI 的全部语义，也没有执行 firmware decoder。硬件仍可能因其他未闭合前提而失败。
- C0/C7 panic 根因未知。未将 bdef7bdf 猜为 MMU 错误，未使用 LastMB 作为有效宏块索引。

以上是剩余验证范围，不是已观察到的新错误。新候选保持原有默认关闭的 submission gate，等待另行明确授权的下一步；本次没有消耗或假设任何新设备试验批准。
